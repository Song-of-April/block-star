# Prompt 0：建立项目和规则文件

你是一名 Android Kotlin 工程师。请在当前目录创建一个可以直接用 Android Studio 打开的原生 Android 项目。

要求：

1. 使用 Kotlin。
2. 使用 Jetpack Compose。
3. 使用 Material 3，但游戏主界面不要呈现普通 Material 应用风格。
4. 包名使用 `com.april.blockstar`。
5. 最低 Android 版本设为 Android 8.0 或更高。
6. 固定竖屏。
7. 不申请 INTERNET 权限。
8. 不添加广告、登录、统计、联网或付费 SDK。
9. 使用单 Activity 架构。
10. 创建以下包：
   - data
   - domain.model
   - domain.engine
   - domain.config
   - presentation.game
   - presentation.components
   - presentation.dialog
   - presentation.theme
11. 创建 `GameConfig.kt`，放置以下可修改常量：
   - BOARD_SIZE = 10
   - CLEAR_BONUS = 15
   - INITIAL_COINS = 200
   - DELETE_TOOL_COST = 50
   - REFRESH_TOOL_COST = 150
   - ADD_TOOL_COST = 150
12. 创建一个最简单的 `GameScreen`，显示“Block Star”文字。
13. 配置 Git 忽略文件。
14. 运行 Gradle 构建并修复所有错误。

此阶段不要实现游戏逻辑，不要做动画，不要添加图片素材。

完成后告诉我：
- 新增了哪些文件。
- 如何运行。
- Gradle 构建是否成功。
- 还有什么未完成。

# Prompt 2：实现基础可玩界面，先用点击操作

请使用已有游戏引擎实现一个基础可玩的 Compose 页面。

界面从上到下：

1. 左上角暂停按钮。
2. 中央显示当前分数。
3. 当前分数下方显示“最高分数：数字”。
4. 右上角显示金币图标和数量。
5. 一行三个临时道具按钮，但暂时禁用。
6. 10×10 棋盘。
7. 底部三个待放置方块。

此阶段先采用简单交互：

1. 点击底部某个方块，将其选中。
2. 点击棋盘某个格子，尝试以该格为锚点放置。
3. 合法则放置。
4. 非法则不改变状态并显示短暂提示。
5. 三个方块放完后自动生成下一组。
6. 死局时显示一个简单弹窗，可以结束并重新开始。

视觉先使用纯色方块和普通网格，不做发光、宝石、星空和动画。

必须实现：

- 当前分数实时更新。
- 最高分在当前运行期间实时更新。
- 金币初始显示 200。
- 使用 ViewModel 和单一 `GameUiState`。
- Compose 只读取状态并发出 Action，不直接修改游戏数据。

构建并运行，确保可以完整玩一局。

# Prompt 8：实现完整死局和金币机制

请完善死局流程。

死局定义：

当前所有尚未放置方块都没有任何合法位置。

死局弹窗要求：

- 显示“没有位置可以放置了”。
- 显示当前分数和最高分。
- 提供删除、刷新、增加、结束本局四个按钮。
- 若金币不足，对应按钮显示价格并置灰或弹出说明。
- 使用道具后若恢复可玩状态，自动关闭弹窗。
- 选择结束本局后显示结算弹窗。
- 结算弹窗提供重新开始按钮。
- 不提供看广告、登录或充值。

金币规则：

- 首次安装 200 金币。
- 每消除一条完整行或列，奖励 5 金币。
- 一次消除两条及以上，额外奖励 5 金币。
- 每局结束按分数奖励：
  - 100～299：10
  - 300～599：20
  - 600 及以上：30
- 一局结算奖励只能发放一次。
- 所有金币变化立即持久化。

将所有数值放入 `GameConfig.kt`。
